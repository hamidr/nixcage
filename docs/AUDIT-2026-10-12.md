# UX and Architecture Audit

- Date: 2026-10-12
- Revision: `877eadc`
- Host: `aarch64-darwin`
- Baseline: `nix develop --command bats --recursive tests/` green, 635 tests,
  5m29s

Every finding below was checked against the code at the revision above. The
ones marked "reproduced" were also run with `NIXCAGE_OS=macos` and a scratch
`XDG_STATE_HOME`. Nothing that needs a Linux builder (the NixOS checks, the
host checks) was run, and no timing was measured.

## Verdicts

### UX

**U1. The first macOS run ends in a timeout over the SSH key.** Valid,
corrected. `ensure_ssh_key` prints the key when it generates it
(`nixcage:210-221`), but `vm_start` then builds and boots the VM anyway with
an empty `authorizedKeys`, and the `BatchMode` wait runs out its 300 s
(`nixcage:236-262`). `status` never prints the key, although the template says
it does (`templates/config/flake.nix:51`, `README.md:216`).

**U2. The macOS template is wrong for macOS by default.** Valid. `hostSystem`
and `microvm.vmHostPackages` are commented out "uncomment on macOS" in a
template that exists only for macOS (`templates/config/flake.nix:37,77`); the
example root is `/home/me/Src`; "Only flake directories" is stale since
ADR-021.

**U3. Every Linux verb asks for a sudo password.** Valid; the proposed fix is
rejected. `enter`, `list`, `status`, `rm` and `exec` all run sudo, and
`modules/host.nix` declares no rule. The claim that `status` fails silently is
wrong: sudo prompts on the terminal, not on the stderr `status` discards. A
NOPASSWD rule for `nixcage-container` is passwordless root, since `enter
--bind` takes any host path, so at most it is an opt-in host option.

**U4. Log lines go to stdout, coloured unconditionally.** Valid, reproduced.
`log_info`, `log_ok` and `log_warn` write to stdout (`nixcage:15-17`), so a
cold-VM `nixcage exec ... | jq`, or an `enter` with a command whose output is
redirected, gets "Starting VM..." in its data, and a pipe receives raw escape codes.

**U5. There is no `nixcage stop`.** Valid, minor, reproduced ("Unknown
command: stop"). A cage ends with its session, so this matters only for a
session that does not end. `README.md:88` lists `stop` among the verbs over a
cage, meaning `nixcage-container stop`, but reads as a CLI verb.

**U6. Flags are parsed after state is checked.** Valid, reproduced. `nixcage
enter --help` answers "VM has not been built yet" because
`check_workspace_root` runs before the flag loop (`nixcage:650` before
`:669`). `--flake` is honoured only as the first word (`nixcage:1159`);
`status --flake x` ignores it without a word.

**U7. `list` cannot be mapped back to a project.** Valid, larger than it
looks. The table shows NAME, SUBSTRATE, STATE, UID, and the name is a
basename plus a hash. The record holds no project path
(`modules/scope.sh:164`), so a PATH column is a change to ADR-017's record,
not only to the table.

**U8. Neither prompt can be scripted.** Valid. Under `set -euo pipefail`, `read
-rp` at EOF exits 1 with no message (`nixcage:582`, `nixcage:1029`).

**U9. Latency paid on every session.** Plausible, not measured. macOS opens a
fresh SSH connection per `enter` and `exec` (no ControlMaster). A flake
project runs `nix eval --impure` over `builtins.getFlake`, which has no
evaluation cache, before `nix develop` evaluates again
(`modules/dev-shell.sh:38`).

**U10. Help and README are stale.** Valid. `exec` help omits `--machine`; an
unknown command dumps the whole help; README still says "four primitives"
(ADR-027 made five) and "the CLI is just enter, rm, and status".

**U11. Internal vocabulary reaches users.** Valid. Undeclared `status` says
"no principalSubjects, since a subject is something a host declares"
(`nixcage:1059-1061`).

**U12. A stray qemu reads as a foreign port.** Valid, low. With the pid file
lost, `vm_start` reports "Port N is already in use" (`nixcage:365`) without
saying the listener is probably nixcage's own VM. The SSH wait shows no
progress for up to 300 s.

**U13. Download sizes are hard-coded.** Valid, low (`nixcage:577-582`).
`docs/MEASUREMENTS.md` is where such numbers are supposed to come from.

**U14. No shell completion, no `status --json`.** Dropped: nothing asks for
either.

**U15. The version is kept by hand twice.** Valid, low. `nixcage:6` and
`package.nix:35`.

### Architecture

**A1. `enter` is ~600 lines of a Nix string that bats cannot reach.** Valid,
the highest risk found. `cmd_enter` and `enter_microvm`
(`modules/container.nix:342-968`) are covered only by the NixOS checks and
`--print-argv`, and `enter_microvm` takes its inputs through dynamic scope:
`cdir`, `owner_uid`, `owner_gid` and `session_home` are `cmd_enter`'s locals
(`modules/container.nix:343-345`). Renaming one breaks microVM sessions with
nothing on macOS to say so.

**A2. The host and VM modules define the same options twice.** Half valid.
`workspaceRoots`, `secretEnv`, `principalUidRange`, `principalSubjects` and
`git` are declared in both, and the declaration is rendered in both. The
reported drift is not drift: ADR-025 decision 6 keeps `CAGE_BINDS` host-only,
and the substrate keys are meaningless where a microVM cannot nest. The real
drift is description text ("Only flake directories" in the VM module).

**A3. Compatibility shims have outlived their stated window.** Valid. They
landed in v5.1.0 (`9f21ef4`) and say "one release"; this is v5.2.2:
`nixcage_declaration_read_legacy` and its callers, the `/etc/nixcage/config`
render in `modules/host.nix`, the `/etc/nixcage/gitconfig` fallback no module
renders, and the `role-uids` rename.

**A4. The Linux/macOS transport branch is repeated.** Valid, low. `cmd_exec`,
`cmd_rm` and `container_records` each branch, but each with its own policy:
`list` refuses to boot the VM, `rm` boots it after confirming, `exec` boots
it. Only the inner two-line branch is common.

**A5. `nixcage_principal_forget` is unwired.** Valid. Only
`tests/unit/principal_uid.bats` calls it.

**A6. macOS has a second reader.** Valid, medium. `vm_read_cache`
(`nixcage:144`) parses its own cache format beside ADR-024's one reader.

**A7. CLAUDE.md is stale.** Valid. It names `/etc/nixcage/config` and
`/etc/nixcage/container`, says the session "execs nix develop", and its
command list omits `list` and `version`.

**A8. `checks` is empty on darwin.** Valid, low. `nix flake check` on a Mac
runs nothing; shellcheck and bats run in CI on ubuntu only.

**A9. `usage()` is one ~900-character line** (`modules/container.nix:162`),
the help of the exported interface, apart from the parser in
`modules/enter-args.sh`. Valid, low.

**A10. `list` pads columns by hand instead of `column -t`.** Invalid. It is
deliberate and says why (`nixcage:844`): `column` is BSD on one platform and
util-linux on the other.

**Loop time.** The suite takes 5m29s, too slow for a loop run after every
change.

### What should stay

- Pure argument builders in `modules/*.sh`, effects in
  `modules/container.nix`.
- One declaration parser shared by the CLI and `nixcage-container`.
- The substrate table and its refusal naming what fixed the substrate.
- Every `modules/*.sh` has a bats file that sources it.
